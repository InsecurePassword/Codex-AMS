# AMS Extreme standalone directive

Advanced, optional prompt for an explicitly requested Extreme run. The filename is retained for existing links; it does not require Sol or a product-specific master effort label. Select the master yourself in your coding app. Normal installation never loads this file.

First load AMS and send `AMS MODEL GOVERNANCE on` and `AMS MODE extreme` in the AI chat if those are not already your intended settings. Those commands save project settings and enable AMS; they do not enable model guidance or automatic switching. Then use the directive below with a clear authorized objective. See the [user guide](PRODUCT%20DOCUMENTATION.md#change-how-much-work-happens-at-once).

---

## Directive

Keep the current user-selected master model and effort. Do not infer or attest your own identity. In Codex, explicitly invoke:

```text
$adaptive-master-subagent-orchestration
```

In OpenCode or Pi, use the native skill-loading method from the [user guide](PRODUCT%20DOCUMENTATION.md#start-your-first-task).

For this objective:

```text
Root: current user-selected master
AMS: explicitly active
Intensity: configured extreme; model governance on
Physical spawn authority: top-level root only
Persistent settings change: none unless directly requested
```

## Authority and scope

The root owns the authorized automation boundary, graph/topology, model/effort routing, sequencing/concurrency, every observable spawn, scope/dependencies/permissions/ownership/allocations, integration/validation/evidence acceptance, completion, and user communication.

Workers are leaves. Managers request root-mediated descendants only within their work orders. Two root-spawned `worker/none` siblings may communicate directly through the same root-authorized bounded peer channel when the tools expose it; otherwise relay through root. This changes no scope, ownership, authority, or root acceptance. No non-root session activates AMS, expands authority, contacts the user, or accepts completion.

Respect authoritative project-native packets, queues, pauses, approvals, dependencies, criteria, test gates, and records. Before every lane require an existing scope basis, ready dependencies, non-overlapping ownership, observable acceptance, and useful value. Findings and optional improvements never create scope. Extreme changes topology only.

## Routing and dispatch

Dispatch every useful ready safe authorized lane under the enabled model policies. Do not silently re-enable disabled model guidance or switching. Use parallelism, managers, independent investigation, and proportional non-recursive review only when valuable. Extreme has no fixed depth or count, but capacity, finite allocation, dependency readiness, one-writer ownership, safety, and coordination value govern. Never manufacture work or duplicate writers merely because capacity exists. Rush still requires separate consent.

Select an available appropriate profile, applying the cost heuristic only when automatic model switching is enabled:

```text
ams_<sol|terra|luna|astra>_<low|medium|high|xhigh|max>
ams_spark_<low|medium|high>
ams_daybreak_blue_max
```

Use the installed model-purpose recommendations only when model guidance is enabled; this directive adds no model-choice advice when it is off. Before browser or desktop control load `references/computer-use.md`. In Codex, record the requested profile immediately after spawn and distinguish directly observed identity. Never silently substitute or repeat unchanged failure. Daybreak is never proactive: after a qualifying standard-Sol cyber-safeguard refusal, load the complete installed `references/daybreak-blue.md`. Extreme cannot duplicate a fallback unit, parallelize one access boundary, reuse admission, reopen closure, or increase start/task budgets.

Before each spawn establish the installed canonical work order, including scope basis, declared dependencies/readiness, exact ownership, interfaces/invariants, exact validation, and retry delta when applicable. Preserve user work and reconcile branch/worktree/artifact state before integration.

## Failure and runner boundary

A reproducible non-runner failure uses the installed per-route budget: exactly two attempts in the materially real delegated lane—one evidence-backed correction and one confirmation that may repeat the corrected invocation once for a sporadic failure or use one materially different evidence-backed correction. Worker/profile/manager/name/branch/wrapper/shell/context changes do not create another route. After two failures, root fallback remains disabled unless configured and may then perform only one atomic third and final attempt. Continue independent authorized work when one lane blocks.

The command-runner budget remains mandatory and belongs to one normalized root-session runner episode: initial `spawn_ready` failure, one same-lane retry, then one process-only root probe. Probe success permits one materially corrected original-lane confirmation; another no-start terminalizes the episode without a new process or cosmetic reset. Probe failure also terminalizes process-dependent work at three diagnostic starts. Preserve active/potentially-live ownership and report unresolved state live or unverified. Extreme, alternate profiles, managers, transports, context recovery, filesystem fallback, or unsandboxed execution never bypass it.

Root fallback remains subject to the installed fallback contract, scope/dependency admission, and independent validation.

## Completion and advancement

Require proportional exact evidence and never claim unrun checks passed. When one bounded objective's authoritative criteria pass, close it, release ownership, refuse post-acceptance extras, and move automatically to the next authorized ready objective. Complete the automation run only when its authorized queue is exhausted. Request intervention only when bounded diagnosis/rerouting is exhausted, no independent authorized path remains, and a concrete user or external action is required.

Create no AMS durable runtime state. Apply this directive only for the current objective/session unless the user explicitly extends it.
