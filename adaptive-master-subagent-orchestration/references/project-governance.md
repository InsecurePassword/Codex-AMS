# AMS project governance

Use only when `project_governance = true`. It is proportional, non-recursive, and non-persistent: no new criteria, acceptance system, durable state, campaign, receipt, or recovery ledger; no change to root authority, routing, hierarchy, permissions, scope, or writer safety.

Maintain the authorized deliverables, criteria, dependencies, critical path, integration order, validation, risks, blockers, and objective states. Project packets, roadmaps, pauses, approvals, trackers, tests, and recording rules remain authoritative. AMS coordinates; it does not redefine them.

Continue automatically while authorized ready work exists. Close accepted objectives and advance. Defer only affected work for unresolved material intent, missing authority for destructive/irreversible/external action, or a required materially different choice. Continue independent work; ask the user only when no autonomous path remains.

Require evidence proportional to the existing risk and criteria: relevant status/commands, diffs, tests/builds/lint/type checks, reproductions, artifact inspection, documentation consistency, and security/architecture/regression review when warranted. Use one normally read-only reviewer for high-risk implementation, security, architecture, broad refactors, difficult defects, or manager integration when practical. Review is proportional and non-recursive. It may fail an existing criterion or report follow-up risk, but cannot invent criteria, expand scope, demand unrelated hardening, implement findings, or reopen accepted work without relevant new evidence.

Root alone reconciles and accepts or rejects. Passing checks, a commit/checkpoint, clean workspace, empty worker set, manager result, or handoff is not completion while mandatory authorized work remains.

Treat unauthorized scope, hidden dependencies, overlapping ownership, expanded parentage/delegation, destructive action, reduced validation, unchanged failure, post-acceptance extras, or conflicting completion claims as deviations. Apply the smallest correction and continue safe independent work.

Use project-native continuity; otherwise return a concise handoff with completed objectives/evidence, active/deferred/blocked work, ownership, next authorized action, and resumption condition. Create no AMS-specific handoff file.
